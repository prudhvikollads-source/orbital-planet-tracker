01Problem

Planet-scale live data is public — ADS-B transponders broadcast every airliner’s position, CelesTrak publishes every tracked satellite’s orbital elements, the USGS streams every significant tremor — but it lives in JSON endpoints nobody watches. Existing trackers are either paywalled, key-gated, or single-feed toys. Nobody had put the living planet in one explorable, keyless view.

02Solution

A static-first mission control: a GitHub Action refreshes three feeds every 5 minutes into compact JSON; a Three.js globe renders thousands of objects as GPU point clouds; satellites propagate live with SGP4; a deterministic analyst answers questions about the scene by text or voice. Zero servers, zero API keys, GitHub Pages hosting.

04Key decisions

ETL + interpolation over client polling. Rate limits and missing CORS headers make direct polling fragile; a 5-minute snapshot cadence respects OpenSky’s anonymous tier while dead reckoning keeps motion smooth.
Honest 2,500-flight cap. A full snapshot is ~600 KB — hostile to static hosting. Deterministic stride sampling keeps it fair, and the UI shows the true airborne total next to the sampled count.
No ships. No keyless global AIS feed exists. Rather than fake vessel dots, the layer doesn’t exist — documented, not silent.
Deterministic analyst. Counts, extrema, and geo-bins are computed from loaded data; the engine cannot hallucinate a flight. The LLM key is an upgrade for open-ended chat only.
One draw call per layer. THREE.Points for 3,000+ objects at 60fps; only the tracked object gets a mesh and trail.

05Example session

  • "How many flights are airborne?" → 11,768 right now (2,500 in this snapshot, refreshed 3m ago).
  • "Where is the ISS right now?" → over the South Pacific at 418 km, 7.66 km/s — globe flies you to it.
  • "Biggest earthquake today?" → M5.9, 62 km from a named place — camera dives to the epicenter.
  • Click any aircraft → chase cam with trail; HUD reads callsign · altitude · speed · heading.
